Dominando $lookup, agregações e relacionamentos

Sistema Escolar • Coleções: alunos, cursos, turmas, professores, contadores

Ferramentas: mongosh + Aggregation Framework

📦 Modelo de dados (premissas)

  • alunos: { _id, nome, email, ativo, bolsista, curso_id, turma_id, endereco: { cidade } }
  • cursos: { _id, nome, departamento, coordenador_professor_id }
  • turmas: { _id, codigo, semestre, curso_id }
  • professores: { _id, nome, departamento }
  • contadores: { _id, valor, descricao }
Pré-requisito: use sistema_escolar • Garanta índices nos campos de junção (curso_id, etc.).
📌 Nota: no mongosh atual, a saída do find() já vem formatada (pretty print) por padrão. O método .pretty(), usado no shell legado, não é mais necessário — por isso não aparece nos comandos desta aula.

📚 Passo a passo de um $lookup básico

Objetivo: mostrar o fluxo mínimo de um join (lookup → project → sort) e como contar/filtrar itens do array.

PASSO 1$lookup junta documentos de duas coleções por igualdade de campos.

PASSO 2$project seleciona e calcula campos finais.

PASSO 3$sort ordena o resultado.

Cursos com seus alunos
db.cursos.aggregate([
  { $lookup: {
      from: "alunos",
      localField: "_id",
      foreignField: "curso_id",
      as: "alunos_matriculados"
  }},
  { $project: {
      nome: 1,
      departamento: 1,
      total_alunos: { $size: "$alunos_matriculados" },
      alunos_ativos: {
        $size: {
          $filter: {
            input: "$alunos_matriculados",
            as: "a",
            cond: { $eq: ["$$a.ativo", true] }
          }
        }
      },
      bolsistas: {
        $size: {
          $filter: {
            input: "$alunos_matriculados",
            as: "a",
            cond: { $eq: ["$$a.bolsista", true] }
          }
        }
      }
  }},
  { $sort: { total_alunos: -1 } }
])
Crie índice em alunos.curso_id: db.alunos.createIndex({curso_id:1})

👥 Consulta reversa: alunos → curso

Objetivo: trazer o objeto do curso por aluno usando $lookup e $unwind, com projeção dos campos úteis.
$lookup + $unwind + $project
db.alunos.aggregate([
  { $lookup: {
      from: "cursos",
      localField: "curso_id",
      foreignField: "_id",
      as: "curso"
  }},
  { $unwind: "$curso" }, // transforma [obj] em obj
  { $project: {
      nome: 1, email: 1, ativo: 1,
      "curso.nome": 1, "curso.departamento": 1
  }},
  { $match: { ativo: true } },
  { $limit: 10 }
])
Se quiser manter alunos sem curso, use: { $unwind: { path:"$curso", preserveNullAndEmptyArrays:true } }

🏆 Ranking por departamento

Objetivo: agregar após o join, consolidando métricas por chave com $group.
$group agregando arrays já juntados
db.cursos.aggregate([
  { $lookup: {
      from: "alunos",
      localField: "_id",
      foreignField: "curso_id",
      as: "alunos"
  }},
  { $group: {
      _id: "$departamento",
      total_cursos: { $sum: 1 },
      total_alunos: { $sum: { $size: "$alunos" } },
      alunos_ativos: { $sum: {
        $size: {
          $filter: { input: "$alunos", as: "a", cond: { $eq: ["$$a.ativo", true] } }
        }
      } }
  }},
  { $sort: { total_alunos: -1 } }
])
No $group, o documento “curso” é reduzido a métricas por _id = departamento.

🔢 Contadores (sequências atômicas)

Objetivo: gerar sequências numéricas atômicas com $inc, evitando colisões.
Ver contadores
db.contadores.find()
Incrementar matrícula
db.contadores.findOneAndUpdate(
  { _id: "matriculas" },
  { $inc: { valor: 1 } },
  { returnDocument: "after" }
)

Por que $inc?

  • Operação atômica → sem duplicidade.
  • Mais rápido que varrer coleção para achar MAX.

👨‍🏫 Professores ↔ alunos via departamento

Objetivo: usar $lookup com pipeline e variáveis (let/$$) para filtrar a coleção “from”.
$lookup com pipeline e variáveis
db.professores.aggregate([
  { $lookup: {
      from: "cursos",
      localField: "departamento",
      foreignField: "departamento",
      as: "cursos_departamento"
  }},
  { $lookup: {
      from: "alunos",
      let: { cursos_ids: "$cursos_departamento._id" },
      pipeline: [
        { $match: { $expr: { $in: ["$curso_id", "$$cursos_ids"] } } }
      ],
      as: "alunos_departamento"
  }},
  { $project: {
      nome: 1, departamento: 1,
      total_cursos: { $size: "$cursos_departamento" },
      total_alunos: { $size: "$alunos_departamento" },
      alunos_ativos: { $size: {
        $filter: { input:"$alunos_departamento", as:"a", cond:{ $eq:["$$a.ativo", true] } }
      } }
  }},
  { $sort: { total_alunos: -1 } }
])
Note o uso de let e $$ para passar variáveis entre estágios do lookup.

🎓 Turmas + cursos + alunos

Objetivo: combinar múltiplos joins e projetar métricas em uma visão por turma.
Múltiplos lookups + unwind
db.turmas.aggregate([
  { $lookup: { from:"cursos", localField:"curso_id", foreignField:"_id", as:"curso" } },
  { $lookup: { from:"alunos", localField:"curso_id", foreignField:"curso_id", as:"alunos_curso" } },
  { $unwind: "$curso" },
  { $project: {
      codigo:1, semestre:1,
      "curso.nome":1, "curso.departamento":1,
      total_alunos_curso: { $size:"$alunos_curso" },
      alunos_ativos: { $size: { $filter:{ input:"$alunos_curso", as:"a", cond:{ $eq:["$$a.ativo", true] } } } }
  }},
  { $sort: { semestre: -1, total_alunos_curso: -1 } }
])
Índice sugerido: db.turmas.createIndex({curso_id:1, semestre:-1})

📊 Relatório 360° por departamento

Objetivo: consolidar professores, cursos e alunos em KPIs por departamento.
$group + múltiplos $lookup encadeados
db.professores.aggregate([
  { $group: {
      _id: "$departamento",
      professores: { $push: "$nome" },
      total_professores: { $sum: 1 }
  }},
  { $lookup: {
      from: "cursos",
      localField: "_id",
      foreignField: "departamento",
      as: "cursos"
  }},
  { $lookup: {
      from: "alunos",
      let: { cursos_ids: "$cursos._id" },
      pipeline: [{ $match: { $expr: { $in: ["$curso_id", "$$cursos_ids"] } } }],
      as: "alunos"
  }},
  { $project: {
      departamento: "$_id", _id: 0,
      total_professores:1,
      cursos_top3: { $slice: ["$cursos.nome", 3] },
      total_cursos: { $size: "$cursos" },
      total_alunos: { $size: "$alunos" },
      ativos: { $size: { $filter:{ input:"$alunos", as:"a", cond:{ $eq:["$$a.ativo", true] } } } },
      bolsistas: { $size: { $filter:{ input:"$alunos", as:"a", cond:{ $eq:["$$a.bolsista", true] } } } }
  }},
  { $sort: { total_alunos: -1 } }
])

🌍 Alunos por cidade e departamento

Objetivo: cruzar localização do aluno com o departamento do curso usando chave composta no $group.
Join + group por campos compostos
db.alunos.aggregate([
  { $lookup: { from: "cursos", localField: "curso_id", foreignField: "_id", as: "curso" } },
  { $unwind: "$curso" },
  { $group: {
      _id: { cidade: "$endereco.cidade", departamento: "$curso.departamento" },
      total_alunos: { $sum: 1 },
      alunos_ativos: { $sum: { $cond: [{ $eq: ["$ativo", true] }, 1, 0] } },
      bolsistas: { $sum: { $cond: [{ $eq: ["$bolsista", true] }, 1, 0] } }
  }},
  { $project: {
      _id: 0, cidade: "$_id.cidade", departamento: "$_id.departamento",
      total_alunos:1, alunos_ativos:1, bolsistas:1
  }},
  { $sort: { total_alunos: -1 } },
  { $limit: 15 }
])

⚡ Performance: índices e explain

Objetivo: garantir IXSCAN com índices corretos e evitar erros de tipagem em curso_id vs _id.

Regra de ouro

  • O tipo de alunos.curso_id deve ser o MESMO de cursos._id.
  • Antes de consultar, DETECTE o tipo para evitar erros ou matches vazios.
1) Descobrir o tipo de curso_id e _id
db.alunos.aggregate([{ $limit: 1 }, { $project: { _id:0, tipo: { $type: "$curso_id" }, curso_id: 1 } }])
db.cursos.findOne({}, { _id: 1, nome: 1 })
2) Montando a consulta conforme o tipo
/* A) ObjectId */
const cursoObj = db.cursos.findOne({}, { _id: 1 })
db.alunos.find({ curso_id: cursoObj._id, ativo: true }).explain("executionStats")
/* B) String */
const cs = db.cursos.findOne({}, { _id: 1 })
db.alunos.find({ curso_id: cs._id, ativo: true }).explain("executionStats")
/* C) Número */
const cn = db.cursos.findOne({}, { _id: 1 })
db.alunos.find({ curso_id: cn._id, ativo: true }).explain("executionStats")
Erros comuns
  • Usar ObjectId("...") inválido (BSONError).
  • Tipos diferentes entre curso_id e _id.
  • Assumir que _id é sempre ObjectId.
Índice composto recomendado
db.alunos.createIndex({ curso_id: 1, ativo: 1 })
Outros índices úteis
db.alunos.createIndex({ turma_id:1 })
db.turmas.createIndex({ curso_id:1 })
db.cursos.createIndex({ departamento:1 })
db.professores.createIndex({ departamento:1 })

📊 Explain saudável

{
  "stage": "IXSCAN",
  "indexName": "curso_id_1_ativo_1",
  "totalKeysExamined": 4,
  "totalDocsExamined": 4,
  "nReturned": 4
}
Procure por IXSCAN. Se aparecer COLLSCAN em consultas críticas, crie/ajuste índices.

Padronização (opcional, recomendado)

  • Padronize curso_id para o mesmo tipo do _id em cursos (geralmente ObjectId).
  • Depois, ative validação com $jsonSchema.

🧰 Guia rápido de estágios

Objetivo: revisar os principais estágios e quando usá-los no fluxo.

Estágios principais

  • $match: filtra documentos no começo do pipeline.
  • $lookup: junta coleções; use índices no localField/foreignField.
  • $unwind: explode arrays em múltiplas linhas.
  • $group: agrega por chave _id.
  • $project: escolhe e calcula campos.
  • $sort, $limit, $skip: ordena e pagina.

Operadores úteis

  • $filter(input, as, cond): filtra elementos de um array.
  • $size(array): tamanho do array.
  • $map, $reduce: transformar/colapsar arrays.
  • $cond: if/else em expressões.
  • $eq, $in, $gte (comparação); $sum, $avg (agregadores).
  • let / $$var: passar variáveis no $lookup (pipeline).

Estágios vs Operadores

  • Estágios são as etapas do pipeline (ex.: {$match: ...}, {$project: ...}).
  • Operadores são funções usadas dentro dos estágios (ex.: $eq, $in, $filter, $cond, $sum).
  • Ex.: {$project: { status: { $cond: [ { $gte: ["$nota", 7] }, "OK", "ATENÇÃO" ] } }}

🔎 $lookup com pipeline (filtro no lado “join”)

Objetivo: filtrar a coleção “from” dentro do próprio $lookup para reduzir dados e ganhar performance.
Cursos com apenas alunos ativos (join já filtrado)
db.cursos.aggregate([
  { $lookup: {
      from: "alunos",
      let: { idCurso: "$_id" },
      pipeline: [
        { $match: { $expr: { $eq: ["$curso_id", "$$idCurso"] } } },
        { $match: { ativo: true } }
      ],
      as: "alunos_ativos"
  }},
  { $project: { nome:1, departamento:1, ativos: { $size: "$alunos_ativos" } } },
  { $sort: { ativos: -1 } }
])
Quando o filtro envolve campos da coleção “from”, use pipeline dentro do $lookup.

🧮 KPIs por curso com $facet

Objetivo: gerar múltiplas visões em paralelo a partir do mesmo fluxo.
Várias visões paralelas
db.cursos.aggregate([
  { $lookup: { from:"alunos", localField:"_id", foreignField:"curso_id", as:"alunos" } },
  { $facet: {
      kpi: [
        { $project: {
            nome:1,
            total: { $size:"$alunos" },
            ativos: { $size: { $filter:{ input:"$alunos", as:"a", cond:{ $eq:["$$a.ativo", true] } } } },
            bolsistas: { $size: { $filter:{ input:"$alunos", as:"a", cond:{ $eq:["$$a.bolsista", true] } } } }
        } },
        { $sort: { total:-1 } }
      ],
      topCursos: [
        { $project: { nome:1, total: { $size:"$alunos" } } },
        { $sort: { total:-1 } }, { $limit: 5 }
      ]
  } }
])
$facet retorna um único documento com múltiplos arrays de resultado (kpi, topCursos).

🧪 Erros comuns e correções

Objetivo: evitar armadilhas frequentes e acelerar a depuração.
  • Usar $this/$$this dentro de $filter → Corrija para as:"a" e $$a.
  • Campos inexistentes em $project → Remova ou proteja com {$ifNull:[ "$campo", valor ]}.
  • Texto solto após ]) no mongosh → Gera “Missing semicolon”.
  • Falta de índice no lado “foreign” do $lookup → COLLSCAN lento.
Dica: Desenvolva por partes. Teste cada $match, depois o $lookup, só então $group/$project.

🧹 Projeções limpas e tipagem

Objetivo: limpar/formatar saída e proteger caminhos nulos com $ifNull.
Selecionando campos essenciais
db.alunos.aggregate([
  { $match: { ativo: true } },
  { $project: {
      _id:0, nome:1, email:1,
      curso_id:1,
      cidade: { $ifNull: ["$endereco.cidade", "N/D"] }
  } },
  { $limit: 20 }
])
$ifNull evita erros quando o caminho não existe.

🔐 Validação por schema (collMod)

Objetivo: aplicar regras ($jsonSchema) para padronizar tipos obrigatórios e bloquear dados inválidos.
Obrigando curso_id/turma_id como ObjectId
db.runCommand({
  collMod: "alunos",
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["nome", "curso_id", "turma_id"],
      properties: {
        nome: { bsonType: "string" },
        curso_id: { bsonType: "objectId" },
        turma_id: { bsonType: "objectId" },
        ativo: { bsonType: "bool" },
        bolsista: { bsonType: "bool" }
      }
    }
  },
  validationLevel: "moderate"
})

🧭 Paginação eficiente

Objetivo: usar range paging por _id para escalar melhor do que skip.
Usando range paging com _id
// Página 1
const page1 = db.alunos.find().sort({ _id: 1 }).limit(20).toArray();
const lastId = page1.length ? page1[page1.length - 1]._id : null;

// Próxima página (guarde e reutilize o _id real, sem converter de novo)
const page2 = lastId
  ? db.alunos.find({ _id: { $gt: lastId } }).sort({ _id: 1 }).limit(20).toArray()
  : [];
Evite skip em coleções grandes; range paging escala melhor.
